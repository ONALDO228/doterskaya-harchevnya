# Дотерская харчевня

Сайт рецептов на чистом HTML, CSS и JavaScript. Без сборщиков, без
библиотек, без конструкторов — файлы открываются в браузере как есть.

Сейчас на сайте, кроме рецептов автора, работает **сообщество**: аккаунты,
отзывы с звёздным рейтингом и свои рецепты посетителей.

## Структура

```
index.html          главная: карточки + кнопка «что готовим наугад»
recipe.html         борщ        } страницы рецептов автора,
bliny.html          блины       } на каждой блок отзывов
salat.html          цезарь      }
carbonara.html      карбонара   }

account.html        кабинет: вход, регистрация, свои отзывы и рецепты
add-recipe.html     форма «добавить свой рецепт»
community.html      народная база: все рецепты посетителей, поиск
recipe-user.html    ОДИН файл под все народные рецепты, id в адресе

style.css           все стили: переменные, флекс-карточки, грид, адаптив
script.js           массив рецептов автора + случайный выбор по клику

store.js            доступ к localStorage: чтение, запись, id, дата, хэш
ui.js               кирпичи для DOM: el(), clear(), stars(), say(), onReady()
auth.js             аккаунты: регистрация, вход, выход, права, панелька
reviews.js          отзывы и рейтинг рецепта
recipes-user.js     рецепты посетителей: форма, база, страница, удаление
notice.js           окно регламента при входе + плашка про хранилище
notice.css          стили этого окна: подключается на всех страницах

img/                картинки блюд
pampasiki/          раздел «Пампасики»: 10 рецептов на одной странице
memasiki/           раздел «Мемасики»: 16 рецептов в data.js, фильтры,
                    замок 18+ (коктейли, закуски, горячее, десерты, мемори)
```

## Как запускать

Двойной клик по `index.html`. Никакой сборки не требуется.

## Сообщество: как это работает

### Аккаунт

Регистрация — логин (технический, латиницей), ник (виден всем) и пароль.
Пароль в открытом виде не хранится нигде: перед записью он сворачивается
в хэш с солью (`Store.hash`). Вход сравнивает хэш введённого пароля с
сохранённым.

После входа в браузер кладётся id пользователя (`dh:session`), а не сам
объект — так переименование или удаление аккаунта не оставляют «призраков».

### Порядок подключения скриптов

```
store.js → ui.js → auth.js → reviews.js → recipes-user.js
```

`defer` выполняет файлы строго в этом порядке, поэтому зависимый всегда
видит того, от кого зависит. Переставить — получить «X is not defined».
При этом сам запуск отложен событием `DOMContentLoaded` (`Ui.onReady`):
к моменту события выполнены ВСЕ скрипты страницы, и `auth.js` спокойно
спрашивает `Reviews` и `UserRecipes`, хотя написан раньше них.

### Отзывы

На каждой странице рецепта внизу блок «💬 Отзывы и оценки»:

* читают все, пишут только вошедшие;
* оценка 1–5 звёзд, средний рейтинг считается автоматически;
* один человек = один отзыв на рецепт: повторная отправка обновляет
  прежний, а не плодит дубли;
* удалить можно только свой отзыв — авторство сверяется по `authorId`,
  и проверка стоит внутри функции, а не только на кнопке.

### Свои рецепты

Форма на `add-recipe.html`: название, эмодзи-обложка, время, порции,
сложность, описание, ингредиенты и шаги (по одному на строку) и совет.
Рецепт появляется в «Народной базе» и начинает выпадать в кнопке
«🎲 Что готовим?» на главной. Удалить — только свой и только самому.

### Окно регламента и плашка про хранилище

При первом заходе на любую страницу появляется окно с правилами сайта
(`notice.js` собирает его сам, вёрстки в HTML нет — иначе текст пришлось
бы поддерживать в тринадцати файлах). Три поведения, и каждое о чём-то
говорит:

| Кнопка | Куда пишется | Что будет в следующий раз |
|---|---|---|
| «Понятно, принимаю» | `dh:rules` в localStorage | окно больше не появится |
| «Прочитаю позже», крестик, Escape, клик по фону | `dh:rules-later` в sessionStorage | в этой вкладке не мешаем, в новой — спросим снова |
| Плашка «Понятно» | `dh:cookies` в localStorage | плашка больше не появится |
| Плашка ушла сама через 30 с | не пишется ничего | появится снова: молчание — не согласие |

Разница между двумя хранилищами как раз и есть смысл кнопки «Позже»:
`sessionStorage` живёт, пока открыта вкладка, поэтому «не согласен» не
превращается в тайное «согласен».

Ссылка «📜 Регламент сайта» в подвале открывает окно повторно — согласие
дали один раз, но перечитать правила когда-нибудь захочется.

Показать окно заново для демонстрации: F12 → консоль → `Notice.reset()`,
затем обновить страницу.

### Где лежат данные

| Ключ | Содержимое |
|---|---|
| `dh:users` | список аккаунтов (только хэши паролей) |
| `dh:session` | id вошедшего |
| `dh:reviews` | все отзывы сайта, у каждого `recipeId` |
| `dh:recipes` | рецепты посетителей |
| `dh:rules` | согласие с регламентом + дата |
| `dh:cookies` | плашку про хранилище закрыли |
| `dh:rules-later` | «прочитаю позже» — это sessionStorage, а не localStorage |

Очистить данные: F12 → Application → Local Storage → удалить ключи,
либо «Удалить аккаунт» в кабинете (стирает и отзывы, и рецепты человека).

## ⚠️ Честно про ограничения

Сервера нет, поэтому всё живёт в localStorage **одного браузера**:

1. Твои отзывы и рецепты не увидит никто другой — ни на другом
   компьютере, ни в другом браузере, ни в приватном окне.
2. Пароль проверяется в браузере, а не на сервере. Хэш здесь примитивный и
   подбирается за секунды: не используй пароль, который где-то уже вводил.
3. Любой, кто открыл консоль, может переписать что угодно. На
   статическом сайте «права» существуют для честных, а не для тех, кто
   хочет сломать.

### Что менять, когда появится сервер

Весь ввод собран в нескольких функциях, поэтому объём правки небольшой:

* `Store.read` / `Store.write` → запросы `fetch()` к API;
* `Auth.register` / `Auth.login` → форма уходит на сервер, ответ —
  кука-сессия вместо записи в `dh:session`;
* хэширование с солью уезжают на сервер (bcrypt или argon2);
* `Reviews.add`, `UserRecipes.add` → тот же код, но с `await`.

Остальное — вёрстка, стили, отрисовка — остаётся как есть.
